# Python BI Studio — Phase 6 Forecasting Research: Model Card

## What is included

**Business scenario stress testing.** Applies an explicitly selected downside or upside change to user-entered *net incremental* annual cash flows. It calculates NPV, IRR (if unique), payback, and scenario ROI through the existing investment engine. Cases are deterministic illustrations, not predicted returns or case probabilities.

**Financial-market historical bootstrap.** Resamples observed historical log-price returns **independently with replacement** to create a bounded distribution of hypothetical future *value trajectories* from a user-entered starting amount. It shows simulated 5th, 50th, and 95th percentiles and the fraction of simulated paths below the starting amount. It is not a trained ML/AI model, confidence interval, real-world loss probability, or a reliable forecast.

**Historical expanding-window backtest.** Compares a simple one-step historical-mean-return forecast with a zero-return/flat-price baseline. Each prediction uses **only earlier returns**; the realization for that date is excluded from training. Reports MAE and RMSE in percentage points. It does not account for data/vendor selection, data cleaning biases, overfitting from model choice, dividends, trade slippage, or transaction expenses. Outperforming a baseline on one historical sample is not predictive of future outperformance.

## Technical safeguards

- At least 60 historical returns, correctly declared daily/weekly/monthly observation spacing; upstream parser rejects duplicates, invalid dates and nonpositive prices.
- Bounded simulation 500–3000 paths and 1–60 observations; bounded numerical inputs; user-selectable deterministic seed for reproducibility.
- No network access, no automatic live market feed, and no changes to active business Dataset Library.
- Market uploaded history is held temporarily in the current session; the new module only caches small derived outputs in Streamlit session state for download stability.
- Results are invalidated when the validated historical price series or simulation controls change.
- Price-only history: splits, distributions, currency conversion, corporate actions, commissions and taxes are not inferred.
- Scenario shock is applied as base_flow +/- abs(base_flow)*percentage; a downside makes negative flows worse.

## Not included yet

- Calibrated forward predictive intervals, live market-data provider integration, time-series ML model fitting/selection, robust multi-instrument portfolio optimisation, regulatory or fiduciary advice, and audited end-to-end large-file website performance.
- No guarantee of capital preservation, gains, or investment performance.

Use this feature for exploratory analysis and software testing, not to make unreviewed financial decisions.

# Accounting definitions and financial verification rules

**Always check the real meaning of source columns.** Synthetic fixtures have explicit field definitions. Do not treat a generic column labelled `Sales` as gross revenue if it is already net of returns or discounts. Never add costs already included in another mapped expense.

| Fixture | Revenue | Cost of sales | Discounts | Returns | Operating expenses | Tax |
|---|---|---|---|---|---|---|
| Retail | `GrossSales` | `CostOfGoods` | `Discounts` | `Returns` | `StoreExpenses` | `TaxExpense` |
| Services | `ServiceFees` | `DeliveryCosts` | `ClientCredits` | `Refunds` | `OfficeExpenses` | `TaxesPaid` |
| Manufacturing | `InvoiceValue` | `ProductionCost` | `TradeDiscount` | `RejectedReturns` | `FactoryExpenses` | `BusinessTax` |

Formulas used by commercial metrics:

- Gross Revenue = sum of the chosen revenue column, **before** separately mapped discounts/returns.
- Net Revenue = Gross Revenue − Discounts − Returns.
- Mapped Costs = Cost of Sales + Operating Expenses + Taxes **only when cost of sales is mapped**.
- Profit After Mapped Costs = Net Revenue − Mapped Costs; this is **not necessarily accounting net profit**.
- Net Business Loss = maximum of (−total mapped profit, 0). Sum of losses on loss-making individual records can differ.
- Profit Margin (%) = Profit After Mapped Costs / Net Revenue × 100; undefined when net revenue is zero.
- Net Profit display requires an explicit confirmation that relevant expense/tax fields are complete. In real accounting, additional items such as financing costs, depreciation, amortisation and other income/expenses may matter.
- ROI is available only when total invested capital is positive and the user has affirmed it is **additive per row**, not a repeated portfolio/account balance.
- Dates with invalid values are excluded from time trends but not business total KPIs.

**Limitations:** No currency conversion, no accrual accounting validation, no automated tax reconciliation and no live financial feeds. Independent bookkeeping/professor review remains a manual gate.

# Public deployment is blocked — security gates

**Do not deploy this iteration as an open multi-user web service.** The current Dataset Library stores uploaded files, labels and `active_dataset.json` in a project-wide directory. Multiple unauthenticated visitors could overwrite or access shared state. Production readiness reports intentionally retain a `BLOCKED_FOR_PUBLIC_DEPLOYMENT` gate.

To clear the gate in a *future* release:

1. **Authentication and authorisation:** Verify each user and enforce per-user dataset access in every uploader, listing, export, switch and deletion path. A cosmetic login screen is not sufficient.
2. **Storage isolation:** Replace `stored_datasets` and global `active_dataset.json` with user-/tenant-scoped storage, protected identifiers and permissions. Confirm cross-user access is impossible with adversarial tests.
3. **Durable persistence:** Use a managed, backed-up store with retention, deletion and restore policies. Ephemeral cloud file systems are unsuitable for durable user libraries.
4. **Privacy:** Review customer names, identifiers, source workbooks, CSV exports and ZIP reports. Never publish real customer-level data as demo assets.
5. **Repository:** Ensure `.venv`, `stored_datasets`, `Data`, `.streamlit/secrets.toml`, `.env`, benchmark CSVs and release reports are excluded from Git. Check `git ls-files` and repository history: `.gitignore` does not remove previously committed files.
6. **Secrets:** Configure remote secrets in deployment settings; never commit plaintext credentials. The preflight reports no secret values.
7. **Controls:** Add upload size and compute budgets, timeout policies, monitoring, incident response, XSRF/CORS review and real-browser security/scale tests.
8. **Dependency review:** Use pinned versions tested on the exact deployment Python version; include a software dependency vulnerability review.

Streamlit Community Cloud currently documents `requirements.txt`/other supported dependency managers, deployment secret settings, and `.streamlit/config.toml` at the project root. See https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/app-dependencies and https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/secrets-management . These official instructions do **not** eliminate the architecture's isolation issues.

# Local Data Safety and Known Limitations

- Only `CSV` and `XLSX` uploads are accepted for the business Dataset Library; this release checks their extension, content, file size (96 MiB), and basic XLSX archive structure before Pandas parsing. This is **not** antivirus scanning or data de-identification.
- Stored dataset names are constrained to safe file basenames and cannot traverse directories or follow symlinks. Active dataset integrity is SHA-256 checked when a hash exists. Older metadata without hashes may still be read, but is marked as legacy in the audit.
- Original local `stored_datasets` is preserved; no automatic destructive migrations or background uploads occur.
- This local single-user architecture is not secure multi-user tenancy. Do not distribute it as a public service.
- Sensitive uploads can remain on local disk. The professor-review ZIP contains *no raw rows or original data values*; nevertheless inspect and selectively share any report containing customer/category labels.
- Financial calculations depend on properly mapped columns and user-confirmed completeness. They do not infer tax, operating expenses or invested capital not represented in the source.
- Market bootstrap/backtesting is historical research, not an AI trained calibrated forecast, live stock feed or guaranteed future result.
- This release tests 500k rows with real underlying modules optionally, including chart-data preparation and HTML report generation. Full browser rendering and all possible 500k interactions are **not** automatically tested.
- The classic Detailed Analytics Dashboard still contains workbook-specific assumptions; prefer Executive Overview for other schemas.
- Local start binds to 127.0.0.1. Other processes, firewall settings, remote desktop, browser plugins and OS permissions are outside this package's control.

# Security, privacy and evidence limits

This is a **local development release** and does not certify production security, regulated financial compliance or investment suitability.

- `run_enterprise_assurance.py` uses deterministic synthetic input unless a test-specific CSV is explicitly supplied. It never updates `stored_datasets/` or `Data/`.
- The Home assurance download includes only column names, data types and missing-count statistics; column names themselves could be sensitive, so review before sharing.
- The SHA-256 manifest checks file integrity against the packaged release. It is not a signed supply-chain attestation and cannot distinguish an independently modified copy from a maliciously replaced package.
- Full-source missing/duplicate scans are opt-in and can consume resources on large datasets. Sampled counts must not be represented as exact full-source counts.
- Financial results rely on user-defined mappings, accounting conventions and one consistent currency. Missing charges and account balances are not silently inferred.
- Investment bootstrap scenarios are historical resampling experiments, **not calibrated confidence intervals or guaranteed future returns**.
- The benchmark is the real module chain but **not** an end-to-end Streamlit performance certification. Browser memory, serialisation, multiple users, chart rendering, and export generation are not included.
- If deploying online, explicitly implement authentication/authorisation and a private storage policy before exposing business data. Nothing in this package implements multi-user isolation.
- The exact full-application 500,000-row release acceptance, final brand consistency and deployment remain planned engineering tasks.
